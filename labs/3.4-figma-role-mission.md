# 3.4 · ภารกิจจริง: Role Skill คู่กับ Figma MCP ตามสายงาน (14 นาที)

**สิ่งที่จะฝึก:** ใช้ Role Skill ของ **BA / QA / Dev** ร่วมกับ `get_figma_data` บนสองโปรเจกต์เดียวกับบันทึกประชุมใน Lab 3.1–3.2

## 1. ติดตั้ง Role Skill ประจำสายงาน (2 นาที)

คัดลอกทั้งโฟลเดอร์โดยเก็บ `SKILL.md`, `references/` และ `assets/` ไว้ภายใน:

| สายงาน | คัดลอกจาก | วางที่ |
|---|---|---|
| BA | `templates/ba/` | `.github/skills/figma-to-spec/` |
| QA | `templates/qa/` | `.github/skills/figma-to-test-cases/` |
| Dev | `templates/dev/` | `.github/skills/figma-to-ui/` |

ทำผ่าน Explorer หรือรันคำสั่งของสายงานคุณจาก workspace นี้:

- **BA:** `mkdir -p .github/skills/figma-to-spec && cp -R templates/ba/. .github/skills/figma-to-spec/`
- **QA:** `mkdir -p .github/skills/figma-to-test-cases && cp -R templates/qa/. .github/skills/figma-to-test-cases/`
- **Dev:** `mkdir -p .github/skills/figma-to-ui && cp -R templates/dev/. .github/skills/figma-to-ui/`

หากมี Skill ชื่อเดียวกันอยู่แล้ว ให้สำรองไฟล์ที่ปรับแต่งก่อนคัดลอกทับ

ดูหน้าต่อยอดใน [แคตตาล็อก Figma](../docs/figma-catalog.md) แต่เริ่มเพียง **หนึ่ง Frame** ให้เสร็จก่อน

### โหมด Offline

หาก MCP ยังใช้ไม่ได้หลังตรวจ Token/เครือข่าย หรือเจอ 429 ให้ใช้ snapshot ตามโปรเจกต์:

- **A:** [Reservation summary](../docs/offline-snapshots/reservation-1439-8969-summary.yaml)
- **B:** [Single Product summary](../docs/offline-snapshots/single-product-518-8937-summary.yaml)

เปิด **New Chat** วางข้อความนี้ ตามด้วย YAML ทั้งไฟล์ แล้วส่ง Prompt ของสายงานในข้อ 3:

```text
Figma MCP ใช้งานไม่ได้ ใช้ Offline Snapshot ด้านล่างแทนข้อมูล live
ห้ามเรียก get_figma_data หรือ download_figma_images และห้ามอ้างว่าอ่าน Figma แบบ live
snapshot เป็นข้อมูลสรุปบางส่วน ถ้าข้อมูลไม่พอให้ระบุว่าไม่มี ห้ามเดา
สำหรับ UI ให้ระบุส่วนที่เป็นสมมติฐานหรือ demo behavior แยกจากสิ่งที่ยืนยันได้

[วาง YAML ของ snapshot ที่เลือก]
```

ใน Prompt ถัดไป เปลี่ยน “อ่านข้อมูลจริงจาก Figma” เป็น “ใช้ snapshot ที่ให้ไว้” และใช้ URL เฉพาะเป็นตัวระบุ Frame ไม่ใช่คำสั่งให้ไปดึงข้อมูล สำหรับ Dev ข้ามดาวน์โหลดภาพและระบุ Token/Spacing ที่ snapshot ไม่ได้ให้เป็นสมมติฐาน บันทึกโหมด Offline ใน Worksheet

## 3. รัน Mission ตามสายงานของคุณ! (7 นาที)

เปิด **New Chat** โหมด **Agent** แล้วเลือก Prompt ด้านล่าง ค่าเริ่มต้นคือโปรเจกต์ A

### BA · Functional Specification

```text
ช่วยเขียน User Story สำหรับหน้าจอนี้ โดยอ่านข้อมูลจริงจาก Figma:
https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=1429-2588&t=7XqB2WyDyrTDj7qi-4

สำหรับ Reservation ให้ครอบคลุมวัน/เวลา จำนวนคน ข้อมูลติดต่อ เงื่อนไข และปุ่ม RESERVE
อย่าเดากฎฟิลด์บังคับ จำนวนคนสูงสุด หรือเงื่อนไขคืนมัดจำ
```

**ตรวจผล:** มี User Story, ตารางอ้าง Node ID, AC และคำถามที่ยังไม่มีคำตอบจากดีไซน์ ไม่เอากฎสมมติมาเขียนเหมือนยืนยันแล้ว

### QA · Test Matrix

```text
ช่วยออกแบบ QA Test Case Scenatio โดยอ่านข้อมูลจริงจาก Figma:
https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=1429-1328&t=7kSNzVJ02gyIfTTS-4

ครอบคลุม Positive, Negative, Boundary และ UI/Design Token Check
```

**ตรวจผล:** ใช้ชื่อฟิลด์จริง มี Test Steps/Expected Result และไม่รายงาน state ที่ยังไม่ได้วาดเป็นบั๊กของระบบที่พัฒนาแล้ว

### Dev · UI Prototype

```text
ช่วยสร้าง UI Prototype แบบ HTML/CSS/JS โดยอ่านข้อมูลจริงจาก Figma:
https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=1429-1328&t=7kSNzVJ02gyIfTTS-4
```

**ตรวจผล:** เปิด [หน้า Preview](../index.html) แล้วเปิด `ui/preview.html` ทดสอบ controls ของโปรเจกต์ที่เลือก สี/ฟอนต์อ้างอิงดีไซน์จริง ไม่ยืม Token จากแอปอื่น

## 4. ตรวจหลักฐานและโบนัส (4 นาที)

- **Online:** เห็น `Read skill figma-to-spec` / `figma-to-test-cases` / `figma-to-ui` ตามสายงาน และ `get_figma_data` ในงานเดียวกัน พร้อมอ่าน checklist/template ของ Skill
- **Offline:** เห็นการใช้ Skill กับ snapshot ที่ให้ ไม่คาดหวัง MCP และไม่อ้างผล live
- บันทึกไฟล์ตามชื่อที่เลือก และจด Design Gap หรือ Token ที่ใช้ใน [Worksheet](worksheet.md)
- ถ้าเสร็จไว: ใช้ **Skill เดิม** กับอีกโปรเจกต์ หรืออ่าน Confirm Reservation / Shop เพิ่ม คน Offline ให้สลับไปอีก snapshot; อย่าดึงทั้งแคนวาส
