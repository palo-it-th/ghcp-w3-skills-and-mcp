# 3.4 · ภารกิจจริง: Role Skill คู่กับ Figma MCP ตามสายงาน (14 นาที)

**สิ่งที่จะฝึก:** ตอนนี้เรารู้วิธีสร้าง Skill (ข้อ 3.1–3.2) และเชื่อมต่อ **Figma MCP Server** (ข้อ 3.3) เรียบร้อยแล้ว!
ในข้อนี้ แต่ละสายงาน (**BA**, **QA**, **Dev**) จะเปิดใช้งาน **Role Skill ประจำตำแหน่ง** เพื่อทำงานร่วมกับ `get_figma_data` บนหน้าจอจริงใน `POC-FIGMA-MCP`

---

## 1. ติดตั้ง Role Skill ประจำสายงานของคุณ (2 นาที)

เราเตรียมแม่แบบ Skill เฉพาะทางของทั้ง 3 สายงานไว้ให้แล้วในโฟลเดอร์ `templates/` เพื่อให้คุณนำไปวางใน `.github/skills/` ได้ทันที (และปรับแต่งเพิ่มได้ตามใจชอบ):

| สายงาน | คัดลอกทั้งโฟลเดอร์จาก | ไปไว้ที่ |
|---|---|---|
| **BA** | `templates/ba/` | `.github/skills/figma-to-spec/` |
| **QA** | `templates/qa/` | `.github/skills/figma-to-test-cases/` |
| **Dev** | `templates/dev/` | `.github/skills/figma-to-ui/` |

คัดลอกโฟลเดอร์ด้วย Explorer ใน VS Code ไปไว้ใน `.github/skills/` แล้วเปลี่ยนชื่อให้ตรงกับคอลัมน์ปลายทาง โดยเก็บ `SKILL.md`, `references/` และ `assets/` ไว้ภายใน หรือรันคำสั่งของสายงานคุณจากโฟลเดอร์ `hands-on/`:

- **BA:** `mkdir -p .github/skills/figma-to-spec && cp -R templates/ba/. .github/skills/figma-to-spec/`
- **QA:** `mkdir -p .github/skills/figma-to-test-cases && cp -R templates/qa/. .github/skills/figma-to-test-cases/`
- **Dev:** `mkdir -p .github/skills/figma-to-ui && cp -R templates/dev/. .github/skills/figma-to-ui/`

หากมี Skill ชื่อเดียวกันอยู่แล้ว การคัดลอกอาจเขียนทับไฟล์เดิม ให้สำรองไฟล์ที่ปรับแต่งไว้ก่อน

## 2. เลือกหน้าจอเป้าหมายจากแคตตาล็อก (1 นาที)

คุณสามารถเลือกทำหน้าจอไหนก็ได้จาก 4 กลุ่มนี้ (ดูรายละเอียดเพิ่มใน [แคตตาล็อกหน้าจอ Figma](../docs/figma-catalog.md)):

| ตัวเลือกหน้าจอ | URL สำหรับส่งให้ Copilot (ระบุ `node-id` เฉพาะเฟรม) | ความท้าทายและจุดเด่น |
|---|---|---|
| **A. Emission Factors Dashboard** *(แนะนำ!)* | `https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=517-7117` | หน้า Admin ครบเครื่อง (`Project ยาดมช่วยชีวิต`): Sidebar, Search, Filter, ตาราง 10 คอลัมน์, Pagination และมี **บั๊กในดีไซน์ซ่อนอยู่ 4 จุด** ให้ BA/QA จับผิด และให้ Dev ฝึกขึ้น Layout ตาราง |
| **B. E-commerce: Single Product (Asgaard sofa)** | `https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=518-8937`<br>*(หรือหน้า Shop: `node-id=518-8657`)* | หน้าสินค้าพร้อมตัวเลือก Size (`L/XL/XS`), Color, ปุ่มจำนวน `- 1 +`, Add To Cart, แท็บรายละเอียด (และมีจุดหลุดในข้อความดีไซน์ให้ BA/QA จับได้!) |
| **C. Component Library & Color Tokens** | `https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=2-3`<br>*(หรือตารางสีเต็ม: `node-id=1-906`)* | ระบบ Design System: ปุ่มหลาย Variants/Sizes, Accordions และ Checkboxes 4 สถานะ เหมาะมากสำหรับสกัด CSS Tokens หรือเขียน Component Spec/Test |
| **D. Register Screen (Page 2)** | `https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=925-1328` | ฟอร์มมือถือกระชับ (`Project ชานมหวานร้อย`) รันไวมาก เหมาะสำหรับผู้ที่ต้องการเห็นผลลัพธ์ครบจบในเวลาสั้นๆ |

> **โหมด Offline — ใช้เมื่อ Figma MCP ยังเชื่อมต่อไม่ได้หลังตรวจ Token/เครือข่าย**
>
> 1. เลือกได้เฉพาะ **A. Dashboard** หรือ **D. Register Screen** เพราะมี Offline Snapshot ให้ใน `docs/offline-snapshots/`; ตัวเลือก B และ C ไม่มี snapshot
> 2. เปิดไฟล์ snapshot ที่ตรงกับหน้าจอ แล้วคัดลอกเนื้อหาทั้งไฟล์:
>    - A: `docs/offline-snapshots/dashboard-517-7117-summary.yaml`
>    - D: `docs/offline-snapshots/register-screen-925-1328.yaml`
> 3. ใน New Chat ให้วางคำสั่งนี้และเนื้อหา YAML ก่อน แล้วตามด้วย Prompt ของสายงานในข้อ 3:
>
>    ```text
>    Figma MCP ใช้งานไม่ได้ ฉันจึงใช้ Offline Snapshot ด้านล่างเป็นแหล่งข้อมูลดีไซน์
>    ใช้ snapshot นี้ทำภารกิจตาม Prompt ที่จะส่งต่อไป ห้ามเรียก get_figma_data หรือ
>    download_figma_images และอย่าอ้างว่าได้อ่านข้อมูลจาก Figma แบบ live
>    ถ้าข้อมูลที่ต้องใช้ไม่มีใน snapshot ให้ระบุว่าไม่มี แทนการเดา
>
>    [วางเนื้อหา YAML ของ snapshot ที่เลือกไว้ตรงนี้]
>    ```
>
>    จากนั้นวาง Prompt ของ BA, QA หรือ Dev ตามปกติ แต่เปลี่ยนคำขอ “ดึงข้อมูลจาก Figma” ให้ใช้ snapshot ที่ให้ไว้ (และใช้ URL ของหน้าจอที่เลือกเท่านั้นเป็นตัวระบุงาน) สำหรับ Dev ให้ข้ามการดาวน์โหลดรูป/โลโก้ เพราะ snapshot ไม่มีไฟล์ภาพ
>    หากเลือก D ให้เปลี่ยน URL ใน Prompt เป็น `https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=925-1328` และปรับชื่อเรื่อง/ไฟล์ผลลัพธ์กับสิ่งที่ให้สร้างจาก Dashboard เป็นฟอร์ม Register (เช่น ไม่ต้องทำ Search/Filter หรือแต่งข้อมูลที่ไม่มีใน snapshot)
> 4. ตรวจผลลัพธ์จากข้อมูลใน snapshot และระบุใน Worksheet ว่าทำงานใน **โหมด Offline**; ในโหมดนี้ไม่ต้องคาดหวังการเรียก `get_figma_data`

## 3. รันภารกิจตามสายงานของคุณ (9 นาที)

เปิด **New Chat** (โหมด **Agent**) แล้วส่ง Prompt ของสายงานคุณด้านล่าง (เปลี่ยนลิงก์เป็นหน้าจอที่คุณเลือกได้ตามต้องการ):

---

### สาย BA · สกัด Requirement, Acceptance Criteria และจับผิด Design Gaps

```text
ช่วยเขียนเอกสาร Functional Specification สำหรับหน้าจอในลิงก์ Figma นี้:
https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=517-7117

ให้ดึงข้อมูลจริงจาก Figma แล้วจัดทำ User Story, ตาราง UI Element & Field Dictionary (พร้อมระบุ Node ID), Acceptance Criteria และลิสต์ Design Gaps / จุดที่ข้อมูลในดีไซน์ขัดแย้งกันเอง เพื่อนำไปถาม Designer
บันทึกไฟล์ไว้ที่ outputs/ba/emission-factors-spec.md
```

**สิ่งที่สาย BA ต้องตรวจในผลลัพธ์:**
1. **โหมด Online:** Copilot เรียกทั้ง **`Read skill figma-to-spec`** (พร้อมเปิดอ่าน `references/checklist.md` และ `assets/spec-template.md`) และเรียก **`get_figma_data`** หรือไม่? **โหมด Offline:** ใช้ Skill และข้อมูลจาก snapshot ที่วางให้ โดยไม่คาดหวังการเรียก MCP
2. ในหัวข้อ **Design Gaps / คำถามที่ต้องยืนยันกับ Designer** จับจุดผิดปกติในดีไซน์เหล่านี้ได้หรือไม่:
   - *(ถ้าทำหน้า Dashboard `517-7117`):* แถวแรก `EF004` สถานะเป็นคำว่า `"Badge"` แทนที่จะเป็น `Active`/`Inactive`, ข้อมูลในตารางมีแถวซ้ำ (`EF001`, `EF006`), ข้อความท้ายตารางบอก `"Showing 7 of 7 factors"` แต่มีปุ่มหน้าถึง `57`, และมี Toast `"Event has been scheduled"` ลอยอยู่
   - *(ถ้าทำหน้า Single Product `518-8937` หรือ Shop `518-8657`):* ชื่อสินค้าคือโซฟา `Asgaard sofa` แต่คำอธิบายสินค้าเป็นลำโพง Marshall Kilburn! หรือในหน้า Shop พิมพ์ `"Short by"` แทน `"Sort by"`
   - *(ถ้าทำหน้า Register `925-1328`):* ไม่มีเงื่อนไขความซับซ้อนของรหัสผ่าน และไม่ได้วาดหน้าจอตอนกรอกผิด (Error state)

### สาย QA · สร้าง Test Case Suite & บันทึก Design Defects

```text
ช่วยออกแบบชุด Test Cases (QA Test Matrix) สำหรับหน้าจอในลิงก์ Figma นี้:
https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=517-7117

ให้ดึงข้อมูลจาก Figma แล้วเขียน Test Cases ให้ครบทั้ง Positive, Negative, Boundary Value, การตรวจ UI/Design Tokens พร้อมสรุปตาราง Design Defects ที่พบจากโครงสร้าง Figma
บันทึกไฟล์ไว้ที่ outputs/qa/emission-factors-test-cases.md
```

**สิ่งที่สาย QA ต้องตรวจในผลลัพธ์:**
1. **โหมด Online:** Copilot เรียกทั้ง **`Read skill figma-to-test-cases`** และ **`get_figma_data`** หรือไม่? **โหมด Offline:** ใช้ Skill และข้อมูลจาก snapshot ที่วางให้ โดยไม่คาดหวังการเรียก MCP
2. ตาราง Test Cases อ้างอิงชื่อฟิลด์และข้อมูลจริงจาก Figma หรือไม่ (เช่น ช่องค้นหา `"Search by name, ID, or source..."`, รหัส `EF004`, `EF005` ที่เป็น `Inactive`, คอลัมน์ทั้ง 10 คอลัมน์ หรือฟิลด์ทั้ง 4 ในหน้า Register)?
3. มีตาราง **Design Defects** ที่ชี้เป้า Node ID ของจุดที่ผิดปกติใน Figma ก่อนที่ทีม Dev จะเอาไปเขียนโค้ดตามผิดๆ หรือไม่?

### สาย Dev · สร้างหน้าเว็บ UI ตาม Design Tokens พร้อมเปิดดูใน Browser

```text
ช่วยสร้างหน้าเว็บ UI (HTML/CSS/JS) ให้ตรงตามดีไซน์ในลิงก์ Figma นี้:
https://www.figma.com/design/pkCT6YDfcnEVOOTS2HIDOg/POC-FIGMA-MCP?node-id=517-7117

ให้ดึงข้อมูล Layout, สี, ฟอนต์ และข้อมูลจาก Figma (หากมีรูปหรือโลโก้ที่ดึงได้ให้ใช้ download_figma_images เก็บไว้ใน ui/assets/)
สกัดสีและระยะห่างเป็น CSS Variables ใน :root และเพิ่ม JavaScript ให้ช่องค้นหาและตัวกรอง Category ใช้งานได้จริง
บันทึกผลลัพธ์ไว้ที่ไฟล์ ui/preview.html
```

*(หมายเหตุสำหรับสาย Dev: หากอยากเริ่มจากฟอร์มมือถือที่รันเร็วมากในรอบแรก สามารถใช้ลิงก์ `node-id=925-1328` หน้า Register Screen หรือ `node-id=2-3` หน้า Component Library ก็ได้)*

**สิ่งที่สาย Dev ต้องตรวจในผลลัพธ์:**
1. **โหมด Online:** Copilot เรียกทั้ง **`Read skill figma-to-ui`** และ **`get_figma_data`** (รวมถึง `download_figma_images` ถ้ามี) หรือไม่? **โหมด Offline:** ใช้ Skill และข้อมูลจาก snapshot ที่วางให้ โดยไม่คาดหวังการเรียก MCP หรือดาวน์โหลดรูป
2. เปิดไฟล์ `index.html` ใน Browser แล้วคลิกปุ่ม **เปิด ui/preview.html** (หรือเปิด `ui/preview.html` โดยตรง):
   - สี, ฟอนต์ `Inter`, การจัดวาง Layout และข้อมูลในตาราง/ฟอร์ม ตรงกับใน Figma หรือไม่?
   - ลองพิมพ์ค้นหาในช่อง Search หรือกดปุ่มดูว่า JavaScript ทำงานได้จริงหรือไม่?

## 3. โบนัสสำหรับคนทำเสร็จไว (3 นาที)

หากทำหน้าจอแรกเสร็จแล้ว ลองเปิด **New Chat** แล้ว:
- ลองเปลี่ยนลิงก์เป็น **อีกหน้าจอหนึ่งในแคตตาล็อก** (เช่น จาก `Dashboard 517-7117` เป็น `Single Product 518-8937` หรือ `Component Library 2-3`) เพื่อพิสูจน์ว่า **Skill ตัวเดิมใช้ซ้ำกับหน้าจอไหนก็ได้ใน Figma!**
- หรือลองสร้าง/ยืม Skill ของอีกสายงานหนึ่ง (เช่น BA ลองสั่งให้สร้าง `ui/preview.html` ต้นแบบ หรือ Dev ลองสั่งให้เจน Test Cases)

**เช็กก่อนทำข้อต่อไป**

- [ ] (โหมด Online) เห็นการทำงานร่วมกันของ **Skill (`Read skill ...`) + MCP (`get_figma_data`)** ในแชตเดียวกัน หรือ (โหมด Offline) ใช้ Skill กับข้อมูลจาก snapshot โดยไม่อ้างว่าเรียก MCP สำเร็จ
- [ ] มีไฟล์ผลลัพธ์จริงใน `outputs/ba/`, `outputs/qa/` หรือ `ui/preview.html`
- [ ] จดสิ่งที่ค้นพบจากดีไซน์จริงหรือ Offline Snapshot ลงใน [แบบบันทึกผล](worksheet.md)
