# 3.2 · ทดสอบการเรียก Skill และแก้ปัญหา Skill ชนกัน (8 นาที)

**สิ่งที่จะฝึก:** เห็นกับตาว่าเกิดอะไรขึ้นเมื่อเพื่อนร่วมทีมสร้าง Skill อีกตัวที่เขียน `description` กว้างเกินไปจน **ทับซ้อน (Overlap)** กับ `meeting-summary` ของเรา (สไลด์ 7–8) แล้วฝึกแก้ให้แต่ละ Skill ทำงานเฉพาะหน้าที่ของตัวเอง

---

## 1. รอบที่ 1 · จำลองเหตุการณ์เมื่อมี Skill คำอธิบายทับซ้อนกัน (4 นาที)

สมมติว่าเพื่อนในทีมเพิ่ง push Skill ตัวใหม่ชื่อ `quick-summary` เข้ามาในโปรเจกต์:

1. ใน Explorer ให้เปลี่ยนชื่อไฟล์ `.github/skills/quick-summary/SKILL.md.off` → เป็น **`SKILL.md`** (ตัด `.off` ออก)
2. ลองเปิดอ่าน `.github/skills/quick-summary/SKILL.md` จะเห็นว่าเพื่อนเขียน `description` กว้างมาก:
   ```yaml
   description: "Use for any task related to summarizing notes, meetings, team chats, documents, or answering questions."
   ```
   แถมข้างในยังสั่งให้ตอบแค่ 3 บรรทัด ห้ามสร้างตาราง และห้ามอ่านไฟล์คำศัพท์อีกด้วย!
3. เปิดดู [รายการคำขอทดสอบ 4 ข้อ](trigger-prompts.md) (มี 2 ข้อที่เป็นงานสรุปประชุม และ 2 ข้อที่เป็นคำถามทั่วไปที่ไม่ควรเรียก Skill เลย)
4. ทดสอบส่งทีละข้อ โดย **เปิด New Chat ใหม่ทุกครั้ง** และ **ห้ามพิมพ์ `/ชื่อ-skill`**
5. สังเกตบรรทัด **`Read skill ...`** แล้วจดผลรอบที่ 1 (ตอนชนกัน) ลงในตารางข้อ 3.2 ของ [แบบบันทึกผล](worksheet.md):
   - โมเดลเผลอไปโหลด `quick-summary` แทน `meeting-summary` หรือไม่?
   - หรือโหลดทั้ง 2 ตัวเข้ามาตีกันใน Context เดียวกัน (และจำไว้ว่าเมื่อโหลดเข้ามาแล้ว **ไม่มีคำสั่ง unload** ออกจากแชตนั้น)?
   - ใน Ask 3–4 (คำถามทั่วไป) เจ้า `quick-summary` แอบโผล่ไปทำงานมั่วด้วยหรือไม่?

---

## 2. รอบที่ 2 · แก้ปัญหา Skill ชนกัน แล้วทดสอบซ้ำ (4 นาที)

จากสไลด์ 7 และ 8 เรามีวิธีแก้เมื่อ 2 Skills ทับซ้อนกันอยู่ 2 วิธีหลัก:

1. **วิธีที่ 1 — ล็อกสิทธิ์การเรียก หรือตีกรอบ `quick-summary` ให้แคบลง:**
   เปิด `.github/skills/quick-summary/SKILL.md` แล้วเลือกทำอย่างใดอย่างหนึ่ง (หรือทำทั้งคู่):
   - เพิ่มบรรทัด `disable-model-invocation: true` ใน YAML frontmatter เพื่อไม่ให้โมเดลหยิบไปใช้เอง (จะทำงานเฉพาะเมื่อผู้ใช้ตั้งใจพิมพ์ `/quick-summary` เองเท่านั้น):
     ```yaml
     ---
     name: quick-summary
     description: "Use only when explicitly asked for a 3-line motivational pitch."
     disable-model-invocation: true
     ---
     ```
2. **วิธีที่ 2 — เขียน `description` ของ `meeting-summary` ให้คมชัด:**
   ตรวจใน `.github/skills/meeting-summary/SKILL.md` ให้ระบุชัดเจนว่าใช้สำหรับ *"team meeting notes, sprint syncs, or chat threads (`sprint-sync`, `retro-chat`) into BA/QA/Dev action items with project glossary and SLA"*

จากนั้น **เปิด New Chat ใหม่** แล้วทดสอบคำขอทั้ง 4 ข้อจาก [รายการคำขอทดสอบ](trigger-prompts.md) อีกครั้ง!
จดผลรอบที่ 2 (หลังแก้) เทียบกับรอบแรกใน [แบบบันทึกผล](worksheet.md)

**เช็กก่อนทำข้อต่อไป**

- [ ] รอบที่ 2: Ask 1 และ Ask 2 โหลดเฉพาะ `meeting-summary` และแปลรหัสโปรเจกต์/SLA ได้ถูกต้อง
- [ ] รอบที่ 2: Ask 3 และ Ask 4 ไม่โหลด Skill ใดๆ เลย
- [ ] บันทึกผล Before / After ใน [แบบบันทึกผล](worksheet.md) เรียบร้อย
