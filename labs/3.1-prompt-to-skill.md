# 3.1 · จาก Prompt File สู่ Agent Skill ตัวแรก (10 นาที)

**สิ่งที่จะฝึก:** เห็นความแตกต่างชัดเจนว่าทำไม **Agent Skill** ถึงดีกว่า **Prompt File** จากสัปดาห์ที่แล้ว (W2) โดยเริ่มจากตัวอย่างงานง่ายๆ ที่ทุกคนในทีม (**BA**, **QA**, **Dev**) เจอทุกสัปดาห์ คือ **การสรุปบันทึกคุยงานให้เป็น Action Items ตามศัพท์และ SLA ของทีม** (ยังไม่ต้องใช้ MCP หรือ Figma ในข้อนี้)

---

## 1. ลองดูข้อจำกัดของ Prompt File แบบ W2 ก่อน (3 นาที)

ในโปรเจกต์นี้มีไฟล์ `.github/prompts/summarize-note.prompt.md` ที่เขียนไว้ตั้งแต่สัปดาห์ที่แล้ว และมีบันทึกคุยงานด่วนของทีมอยู่ที่ `docs/sample-notes/sprint-sync.md` (ลองเปิดอ่านดู จะเห็นโค้ดเนมสุดกาวของทีม เช่น `Project หมูกระทะ`, `Project ยาดมช่วยชีวิต`, `SLA-Red`, `SLA-Amber`)

ลองเปิด **New Chat** (โหมด **Agent**) แล้วพิมพ์ถามตามธรรมชาติ (**โดยไม่พิมพ์ `/summarize-note`**):

```text
ช่วยสรุปบันทึกประชุมใน #docs/sample-notes/sprint-sync.md เป็นงานที่ต้องทำต่อให้หน่อย
```

**สังเกตผลลัพธ์ที่ได้:**
1. **Prompt File ไม่ถูกเรียกใช้:** เพราะ `.prompt.md` จะทำงานก็ต่อเมื่อคุณจำชื่อแล้วพิมพ์ `/summarize-note` เรียกเองเท่านั้น (แถมรันได้เฉพาะใน Local session target)
2. **พกไฟล์ความรู้และแม่แบบไปด้วยไม่ได้:** Copilot ไม่รู้เลยว่า `Project หมูกระทะ` จริงๆ คือ *ระบบแลกคูปองและสะสมแต้ม* (ไม่ใช่ระบบปิ้งย่าง!) หรือ `Project ยาดมช่วยชีวิต` คือ *ระบบแดชบอร์ดคำนวณคาร์บอน* และ `SLA-Red` แปลว่าต้องแก้ภายใน 4 ชั่วโมง เพราะ Prompt File เป็นแค่ไฟล์เดี่ยวๆ ไม่มีที่เก็บคลังคำศัพท์ (`references/`) หรือตารางแม่แบบ (`assets/`)

---

## 2. สร้าง Agent Skill ตัวแรกของคุณ: `meeting-summary` (4 นาที)

คราวนี้เราจะแพ็กงานนี้ใหม่ให้เป็น **Agent Skill** ที่ `.github/skills/meeting-summary/`:

1. สร้างโฟลเดอร์ `.github/skills/meeting-summary/`
2. คัดลอกโฟลเดอร์ `references/` และ `assets/` จาก `templates/simple-skill/` ไปไว้ใน `.github/skills/meeting-summary/` ทั้งโฟลเดอร์
3. สร้างไฟล์หลักชื่อ `.github/skills/meeting-summary/SKILL.md` แล้วใส่เนื้อหานี้:

```markdown
---
name: meeting-summary
description: "Use when summarizing team meeting notes, sprint syncs, or chat threads into role-based action items (BA, QA, Dev) with decoded project names and SLA deadlines."
---

# Team Meeting & Chat Summary Skill

เมื่อผู้ใช้ขอให้สรุปบันทึกการประชุม โน้ตคุยงาน หรือแชตของทีม:

1. เปิดอ่านคำศัพท์รหัสโปรเจกต์และกรอบเวลา SLA ใน [Team Glossary](references/team-glossary.md) เพื่อแปลรหัสทุกตัวให้เป็นชื่อระบบและเวลาจริง
2. จัดรูปแบบผลลัพธ์ตามโครงสร้างใน [Summary Template](assets/summary-template.md) โดยแยกตารางงานของ BA, QA และ Dev ให้ครบ
3. สรุปตอบในแชตได้ทันที (เว้นแต่ผู้ใช้สั่งให้บันทึกเป็นไฟล์)
```

> **เช็กโครงสร้างโฟลเดอร์ (ตามสไลด์ 5 · Skill Anatomy):**
> ```text
> .github/
>   skills/
>     meeting-summary/
>       SKILL.md
>       references/
>         team-glossary.md
>       assets/
>         summary-template.md
> ```
> - `name` ใน YAML ต้องตรงกับชื่อโฟลเดอร์ `meeting-summary` เป๊ะ
> - `description` ต้องครอบด้วย `"..."` เพราะเป็นประโยคที่ Copilot ใช้ตัดสินใจว่าจะหยิบ Skill นี้ขึ้นมาใช้หรือไม่
> - ไฟล์ใน `references/` และ `assets/` ต้องถูกลิงก์จากใน `SKILL.md` เพื่อให้ Copilot เปิดอ่านต่อได้เมื่อจำเป็น (Progressive Disclosure)

## 3. ทดสอบถามประโยคเดิมอีกครั้งใน New Chat! (3 นาที)

เปิด **New Chat ใหม่** แล้วส่งประโยคเดิมเป๊ะๆ (**ไม่ต้องพิมพ์ `/meeting-summary` และไม่ต้องแนบไฟล์คำศัพท์เอง**):

```text
ช่วยสรุปบันทึกประชุมใน #docs/sample-notes/sprint-sync.md เป็นงานที่ต้องทำต่อให้หน่อย
```

**ดูความเปลี่ยนแปลงที่เกิดขึ้นใน Chat (เทียบกับสไลด์ 6 · How a skill loads):**
1. Copilot เห็น `name` + `description` ของ `meeting-summary` แล้วตัดสินใจโหลดเองอัตโนมัติ → ขึ้นบรรทัด **`Read skill meeting-summary`**
2. พออ่าน `SKILL.md` จบ มันตามลิงก์ไปเปิดอ่าน `references/team-glossary.md` และ `assets/summary-template.md` เอง!
3. ตารางผลลัพธ์แปลโค้ดเนม `Project หมูกระทะ` → *ระบบแลกคูปองและสะสมแต้ม*, `Project ยาดมช่วยชีวิต` → *ระบบแดชบอร์ดคำนวณคาร์บอน*, `SLA-Red` → *ต้องแก้ไขภายใน 4 ชั่วโมง* และจัดตารางแยก BA / QA / Dev ตามแม่แบบเป๊ะ!

**เช็กก่อนทำข้อต่อไป**

- [ ] เห็นความต่างระหว่าง Prompt File (ต้องเรียก `/name` เอง, ไฟล์เดี่ยว) กับ Skill (Agent เลือกใช้เองจาก `description`, พก `references/` + `assets/` ไปเปิดอ่านเมื่อต้องใช้)
- [ ] เห็นบรรทัด `Read skill meeting-summary` และการเปิดอ่าน `team-glossary.md` กับ `summary-template.md`
