# QA Checklist · การออกแบบ Test Cases จากดีไซน์ Figma

เมื่ออ่านโครงสร้างหน้าจอจาก Figma (`get_figma_data`) ให้ตรวจสอบว่าชุด Test Cases ครอบคลุม 5 มิตินี้:

1. **Positive Cases (Happy Path):**
   - ทดสอบ Flow หลักตามข้อมูลตัวอย่างที่ปรากฏใน Figma (เช่น กรอกฟอร์มครบทุกช่อง, ค้นหาข้อมูลที่มีอยู่ในตาราง, กดปุ่มหลัก)
2. **Negative & Validation Cases:**
   - ทดสอบเว้นว่างช่องบังคับหรือรูปแบบข้อมูลผิดเมื่อมีการยืนยัน required status และ validation rule แล้ว
   - ห้ามอนุมานว่าฟิลด์บังคับหรือรูปแบบข้อมูลจาก placeholder/ตัวอย่าง หากกฎยังไม่ชัด ให้บันทึกเป็นคำถามและระบุ Test Case ว่ารอคำยืนยัน
3. **Boundary Value Analysis (BVA):**
   - ทดสอบค่าต่ำสุด/สูงสุดและขอบเขตอื่นเมื่อมีการยืนยันกฎและขอบเขตแล้ว
   - ห้ามกำหนดค่าต่ำสุด/สูงสุดจากค่าตัวอย่างใน Figma; หากยังไม่มี rule ให้บันทึกเป็นคำถามแทนการสร้าง Expected Result เอง
4. **UI & Design Token Verification:**
   - ตรวจข้อความบนหัวข้อ/ปุ่ม, สีหลัก (Hex code), ฟอนต์ และสถานะ Badge/Checkbox ให้ตรงกับค่าใน Figma
5. **Design Defect Log (บั๊กตั้งแต่ในดีไซน์):**
   - บันทึกจุดที่ข้อมูลใน Figma ขัดแย้งกันเอง (เช่น ข้อความ `"Badge"` ที่ลืมแก้, แถวข้อมูลซ้ำ, จำนวนรวมไม่ตรงกับ Pagination, หรือคำสะกดผิดอย่าง `"Short by"`)
